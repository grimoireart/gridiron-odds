# Gridiron Odds

A daily NFL cross-check for recreational betting. For every game of the current season the page
shows a predicted winner, a predicted score, a confidence tier, a *Why?* rationale built only from
the model's own inputs, the best available moneyline among a few US books, and a parlay panel that
ranks the slate's combinations by expected value. Under the hood: an Elo model with a quarterback
adjustment replayed over every game since 1999, one official odds snapshot per day, and a blended
model-plus-market probability.

**What it is not.** It is not a claim of an edge. The model's 2025 holdout Brier (0.216 with the QB
term) is worse than the closing market's (0.210); the blend weight the data chose is 0.05, so the
headline probability is almost entirely the closing market. The page says so. Most prices show a
negative "model-estimated EV"; the useful output is *which price is best* and *which spots look
bad*, plus a frozen, graded pick ledger so the model's record is public and un-editable.

## Layout

```
src/        data.py (nflverse fetch/cache)  elo.py + qb.py (ratings)  evaluate.py / tune.py (holdout, grid)
            market.py (odds math, feed normalization)  predict.py (official pick, factors, rationale)
            parlay.py (Python oracle for the page's parlay engine)  simulate.py (season sim)
            ledger.py (append-only picks.jsonl + reducer)  build.py (orchestration)  render.py + page_template.html
proxy/      odds.js (optional Cloudflare Worker: live price overlay)  wrangler.toml  test_odds.mjs
tests/      unittest suite + fixtures; browser_check.mjs (Playwright smoke test)
docs/       SPEC.md  DECISIONS.md (wins over everything)  CONTRACT.md (model.json / ledger / overlay)  RUNBOOK.md
params.json tuned parameters + holdout numbers (make tune)      data/games.csv  cached nflverse file (gitignored)
model.json, index.html, picks.jsonl   generated by make build (committed by the daily Action)
```

## Commands

Python 3.11+ standard library only; the interpreter is `python3`.

| command | what it does |
|---|---|
| `make build` | fetch games.csv -> Elo replay -> official odds (or CSV lines) -> predictions -> season sim -> ledger -> `model.json` + `index.html` (+ appends to `picks.jsonl`). About half a second offline. |
| `GRIDIRON_OFFLINE=1 make build` | same, using the cached `data/games.csv` without downloading |
| `make tune` | grid search -> `params.json`; prints the 2025 holdout table |
| `make test` | `python3 -m unittest discover -s tests` + the Elo reference check (2025 Brier within +/-0.003 of `params.json`) |
| `make serve` | `http://localhost:8787` static server for the built page |
| `node tests/browser_check.mjs` | Playwright smoke test of the rendered page (`npm install playwright` in the repo root, or `PLAYWRIGHT_MODULE=/path/to/node_modules/playwright/index.mjs`; exits 2 with a message when Playwright is absent) |

Environment variables the build reads — nothing else:

- `GRIDIRON_OFFLINE=1` — skip the nflverse download and use the cache.
- `ODDS_API_KEY` — if set, the build makes ONE call to The Odds API (3 credits) for the official
  snapshot and `build.odds_source` is `"odds_api"`; otherwise the CSV closing lines are used.
- `GRIDIRON_ODDS_URL` — the optional Worker URL embedded in the page as `window.GRIDIRON_ODDS_URL`
  for the LIVE price overlay. Empty = overlay off; the page shows "Lines as of build time".

## How a build works

1. `data.fetch_games` downloads nflverse `games.csv` to a temp file, validates it (columns, unique
   ids, paired scores, season counts, row count not far below the cache) and atomically replaces the
   cache; any failure keeps the old cache and fails the build.
2. `elo.replay` processes every played game since 1999 in chronological order (rollover once per
   season, QB term keyed by nflverse id) and records the PREGAME probability of every game.
3. `market.fetch_official_odds` is called once if `ODDS_API_KEY` is set; games are matched by
   canonical team codes within 36 h of kickoff. Unmatched or keyless -> CSV lines for that game.
4. `predict.predict_game` produces the immutable `official` object per game (pick, probabilities,
   tier, scores, factors, rationale, edge chip) and `simulate.simulate` runs 10,000 seeded seasons.
5. `ledger.append_snapshots` / `append_grades` compute the new append-only events (a snapshot only
   when the official fields changed; one grade per finished game) and `ledger.reduce` folds the whole
   ledger into the track record.
6. `schema.validate_model` must return no problems; only then are `picks.jsonl` appended and
   `model.json` / `index.html` written atomically.

The official pick, probability, tier and rationale are frozen at build time. The browser overlay
(if the Worker is deployed) may only change the displayed best price, live EV and a "price moved"
note under a LIVE label.

## Going live — the three things the owner must do

Nothing in this repo pushes, deploys, or spends credits on its own. To publish:

1. **Create the GitHub repo and enable Pages.** Push this repository to a personal GitHub repo
   (`main` branch), then *Settings > Pages > Source: GitHub Actions*. The workflow in
   `.github/workflows/daily.yml` runs at 10:00 UTC daily (Sep-Feb) and on manual dispatch; it
   commits only `model.json`, `index.html`, `picks.jsonl`, `params.json`, and deploys `index.html`.
   Run it once by hand (*Actions > daily build > Run workflow*) to seed the page.
2. **Add the `ODDS_API_KEY` secret** (*Settings > Secrets and variables > Actions*). Free tier at
   the-odds-api.com. Without it the build still works from CSV closing lines (`odds_source: "csv"`).
3. **Deploy the Worker (optional live prices) and point the page at it.** In `proxy/`:
   `npx wrangler secret put ODDS_API_KEY`, set `ALLOWED_ORIGINS` in `proxy/wrangler.toml` to the
   Pages origin (`https://<user>.github.io`), `npx wrangler deploy`, then set the repository
   variable `GRIDIRON_ODDS_URL` to the Worker URL. The Worker ignores caller parameters, caches 15
   minutes, coalesces misses, and stops calling upstream when fewer than 60 credits remain.

Day-to-day operation, failure modes and recovery are in `docs/RUNBOOK.md`.
