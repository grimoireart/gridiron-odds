## Ground truth already verified (do not re-derive)
- nflverse games.csv: 7,548 rows 1999-2026; 2026 = 272 REG rows, 65 played as of 2026-10-09. Future rows beyond ~week 6 have BLANK qb names/ids, spread_line, total_line, moneylines. 259 historical rows have blank gametime. 15 ties in the file. Same QB display name can map to two `*_qb_id`s.
- Spec Elo formula reproduces the prototype exactly: 2025 holdout n=285, Brier 0.2209, logloss 0.634 (sort by gameday,gametime; ties s=0.5; d_fav = +d home win / -d away win; rest diff 0 when a rest field is blank).
- QB adjustment (keyed by NAME in the check) passes the gate: KQ=6, Q0=-50, QREV=0.2 gives 2025 holdout Brier 0.2173 (< 0.2209). Tune KQ in {4,6,8,12}; expect ~6.
- Pure-Python 10k-run season sim with playoffs runs in 0.4 s on Python 3.14. NO NumPy anywhere. Stdlib only, Python 3.11+ compatible syntax (no 3.12+ only features).
- The Odds API bills credits = markets x regions. h2h+spreads+totals in regions=us = 3 credits/request. Free tier 500 credits/month => ~166 requests. Headers x-requests-remaining / x-requests-used / x-requests-last. Response: list of {id, commence_time (UTC ISO), home_team, away_team (full names), bookmakers:[{key,title,markets:[{key:'h2h'|'spreads'|'totals', outcomes:[{name, price, point?}]}]}]}. Book keys: draftkings, fanduel, betmgm, williamhill_us (Caesars), plus others.

## Decisions
D1. Elo: spec formula + `tie_multiplier` param (default 1.0: a tie uses mult=1, s=0.5). Regenerate the reference in params.json from this code; the acceptance band is +/-0.003 of the recorded value. Chronology key: (season, gameday, gametime-missing-last, gametime, game_id). Rollover exactly once before each season's first game.
D2. QB: ENABLED (gate passed). Key by `home_qb_id`/`away_qb_id`; names are display only. New ID starts at Q0=-50. Q update = KQ*mult*(s-p) (home +, away -). Between seasons Q *= 0.8. Inactivity: lazily, before a QB's next game, apply -25 per COMPLETED 365-day gap since last start (pure function of elapsed days; applied once per completed year, never compounding with the season regression). Store last_start_date per ID. If a future game's starter is blank: QB term = 0 for that side, `availability.starter_*=false`, rationale omits the QB sentence, card shows "starter not listed". Rationale calls the starter the "listed starter". A listed starter with no history ("first start on record") is said as such, never "rates X below the usual starter". The "usual starter" = the team's most frequent starter ID over its last 8 played games.
D3. Blend (AMENDED 2026-10-09): the weight is PINNED at 0.35. The fit on 2015-2024 against closing lines (recorded as blend.fitted_model_weight, ~0.05) would make the page a market mirror, so the fitted value and its holdout cost are reported beside the pinned one. Original text: w fit on 2015-2024 against CSV closing lines (grid 0..1 step 0.05, Brier); report 2025 model/market/blend Brier separately in params.json; page copy says "blend against the closing market". Expect w near 0.35; whatever the fit says, use it.
D4. Tiers (favorite's p_blend): Toss-up <0.55, Lean 0.55-0.65, Strong 0.65-0.78, Lock-ish >=0.78. These four names everywhere.
D5. Score (AMENDED 2026-10-09): the spread used for the score is the BLENDED spread, read off p_home_blend by inverting the Elo curve (d = 400*log10(p/(1-p)), spread = d/25), so the predicted score always agrees with the pick; model_spread (d/25) stays in official for the Why? text. Favorite for the tie-nudge = the pick. Original text: expected_home = (total + spread)/2, expected_away = (total - spread)/2 kept unrounded; display ints = round(); if equal, add 1 to the favorite (favorite = home when p_home_model >= 0.5). Total source priority: official odds consensus median total -> CSV total_line -> league-average total of the previous full season (computed, not hardcoded). Record `total_source`.
D6. Odds: the DAILY BUILD is the official snapshot. build.py calls The Odds API directly once if ODDS_API_KEY is set (else uses CSV lines, `market.source="csv"`). The Worker is an OPTIONAL live overlay: fixed upstream URL (ignores caller params), Cache API with one canonical key, 15-min TTL, coalesced misses, CORS allowlist (ALLOWED_ORIGINS env, comma list), and a hard reserve: if upstream `x-requests-remaining` < 60 it stops calling upstream and serves stale-or-empty with `{"degraded":true}`. The page treats the overlay as "live prices" ONLY: it may update best price / live EV / a "market moved" note under a clear LIVE label; it NEVER changes the official pick, probability, tier, rationale or record. Overlay contract: {schema_version, fetched_at, degraded, games:[{home, away (canonical codes), commence_time, books:[{key, home_ml, away_ml, home_spread, total}]}]} — the Worker does NOT canonicalize; the page/market.py does via a full-name map. Matching: canonical teams first, then |commence_time - kickoff_utc| <= 36h; ambiguity => no match (fail closed to embedded).
D7. Kickoff: `kickoff_utc` from gameday+gametime interpreted as America/New_York (zoneinfo; blank time => 13:00 ET, flagged `time_known=false`), `league_date` = gameday. "Today" on the page = games whose league_date equals the viewer's current date in America/New_York; if none, show the next league date with a "Next slate: Sun Oct 12" label. Kickoff rendered in the viewer's local zone.
D8. EV label: "Model-estimated EV at this price". Positive styling only when EV >= +0.02 per $1. CLV = same-side no-vig probability movement, pick-time consensus vs CSV close, in percentage points (not cents); best-price move shown descriptively as "price moved".
D9. Parlay: per-book enumeration. For each selected book, legs = favorites (official pick) with p_blend >= 0.55 that have an h2h price at that book; 2-5 legs, no two legs from the same game; hit = product p_blend; payout = product of decimal odds - 1; EV = hit*payout - (1-hit); fair American from 1/hit. Rank by EV; pin best 2/3/4-leg; show hit%; toggle legs; sort toggle EV / hit%. Computed in the browser from official fields; `src/parlay.py` is the Python oracle that tests compare against (shared fixture). Copy: "Parlays multiply the house edge. Most of these have negative expected value; the ranking shows which lose least. Legs are treated as independent."
D10. Ledger: `picks.jsonl` is APPEND-ONLY events. Event types: `snapshot` {id = game_id + "@" + build_id, game_id, kickoff_utc, build_at, pick, p_model, p_market, p_blend, tier, pred_home, pred_away, best_price, best_book, ev, market_source, qb_home_id, qb_away_id, qb_home, qb_away, consensus_p_pick} and `grade` {snapshot_id, game_id, graded_at, result (home|away|tie), margin, home_score, away_score, hit (true|false|null for tie), close_p_pick (no-vig from CSV close for the picked side), close_price_pick (CSV ML for the picked side), clv_pp}. Rules: a build writes a snapshot for a game only if the official fields differ from the game's latest existing pre-kick snapshot (so reruns add nothing); a grade is written once per game, for the latest snapshot with build_at < kickoff_utc; nothing is ever edited. Reducer (ledger.py) computes track record: overall (n, W-L-T, accuracy, market accuracy on the same games), by tier, by week cumulative (model vs market), calibration (10 bins, low_sample flag <10), score MAE (margin, total) vs market, CLV (pp, share moved toward pick), units at best price (all picks, EV>=0 picks) with break-even = 1/(1+payout) shown per price and 52.38% for -110. Ties: push, excluded from accuracy and units. Every aggregate carries n.
D10a (2026-10-11). Kicked-off games are DISPLAYED from their graded pre-kick snapshot (CONTRACT 2.6a); the build never recomputes a card after kickoff. Snapshot events gain total_used/total_source.
D11. Sim: regular-season rows only; frozen team Elo + HFA + rest (no QB term); 10,000 runs, seed 2026; playoff approximations noted on page. Metadata in `src/teams.json` (code, name, city, conference, division, full_name_aliases for the odds feed). Tests check sums within Monte Carlo tolerance (7 +/- 0.01 per conference, 1.0 +/- 1e-9 for SB since it is a count/N).
D12. Data: download to temp, validate (required columns, unique game_id, scores paired, allowed teams after alias, season counts plausible, row count >= cached-1000), sha256, atomic replace; on failure keep the cache and fail the build loudly. Cache at data/games.csv (gitignored). `GRIDIRON_OFFLINE=1` uses the cache without fetching.
D13. Front end: static index.html = page_template.html with `<script id="model" type="application/json">` holding model.json (escaped: `</` -> `<\/`, U+2028/2029 escaped). JS reads it with JSON.parse. No innerHTML with feed strings (use textContent / createElement; a tiny h() helper). Eyrie design (docs/eyrie-tokens.css): white paper, ink text, JetBrains Mono for every label/number/button, Archivo for display, Inter body; cyan (#00d4ff fills, #007391 as text) is the pick accent; --hyp amber for edge chips; --signal purple for the parlay panel; --qualified green for a hit, --danger for a miss; dot-grid canvas. Fonts via fonts.googleapis.com with real fallbacks. Light + dark (both guarded blocks as in the tokens file). 400px: no body horizontal scroll (tables scroll inside .tablewrap). Tabs: Today / Rankings / Track record / How it works; keyboard operable (role=tablist, arrow keys), aria-expanded on Why? and parlay rows, visible focus, reduced-motion respected, status never color-only.
D14. Hosting: GitHub Pages + Actions (not work-related; GitHub is fine). Personal repo (grimoireart), decided by Lauren later; nothing is pushed by the build team. Actions: cron 0 10 * * * Sep-Feb, workflow_dispatch, `concurrency: gridiron-build` with cancel-in-progress false, permissions contents: write, `git pull --rebase` before push, commit only model.json index.html params.json picks.jsonl, fail loudly on push failure. The deploy job publishes the repo root (index.html) with actions/deploy-pages.
D15. Commands: `make build` (fetch->rate->predict->sim->ledger->model.json->index.html, < 30 s), `make tune`, `make test` (python -m unittest discover tests + reference check), `make serve` (python -m http.server 8787). No third-party Python packages. Tests use unittest (stdlib).
D16. Books default: draftkings, fanduel, betmgm, betrivers (verified 2026-10-09 against the live feed: DK/FD/BetRivers price all 26 games, BetMGM 14, Caesars/williamhill_us is ABSENT from the feed, mybookieag/bovada/betus/betonlineag/lowvig are offshore and excluded). Lauren uses no book yet, so these four are a price-shopping reference, not a recommendation. User toggles persisted in localStorage (try/catch). A real live sample of the h2h feed is at docs/odds_api_live_sample_h2h_2026-10-09.json.
D17. Edge chip: amber chip when |p_model - p_market| >= 0.08 for the pick side; one line naming ONLY a measured factor: a starter change vs usual starter ("listed starter differs from the usual starter"), rest gap >= 3 days, or a >= 40-point Elo move over the last 3 games ("rating moved N points in the last three games"); otherwise "may reflect information this model lacks". Never "injury news" unless a starter change is measured.
D18 (2026-10-13). Injury reports. D18.1 Source: nflverse `injuries_{season}.csv` (the league's official weekly report: Out / Doubtful / Questionable, Probable before 2016) + `depth_charts_{season}.csv` (`pos_rank == "1"` = starter, per unit, Special Teams and K/P/LS/KR/PR/H never starters); cached under data/ (gitignored), D12-style fetch; a missing file never fails the build — it degrades to `available: false` and the card says "injury reports unavailable this build"; an unfiled week (bye, or before the league publishes it) is "no report filed yet", which is NOT "nobody hurt". D18.2 Contract: `official.injuries` (CONTRACT 2.6b, 7 keys; reports of 8 keys; players of 8 keys), `build.injuries` (2.2), `params.injury` (2.3, 4 keys), snapshot `injury_elo`/`inj_home`/`inj_away` (4.1, informational — not in the snapshot difference rule), `track_record.by_injury_load` (2.12). D18.3 Page: an Injuries block on every card (per team: starters Out/Doubtful/Questionable with names, "Full report" table, QB rows marked "covered by the QB term"), every string via textContent; "How it works" states the gate verdict and the weights; Track record splits by injury load. D18.4 Text: the `injuries` rationale sentence (between `rest` and `form`) fires iff a starter is listed Out or Doubtful on either side; reports LISTED statuses only, never speculates; ends "shown for context, not in the number yet" while disabled, "worth about N points to {City}" when enabled. Edge chip `reason_key` `injuries` sits between `starter_change` and `rest_gap` (a listed starter is a measured factor; D17's "never injury news" means never UNMEASURED injury talk). D18.5 Ledger: snapshots carry the term and both summaries; the reducer buckets graded picks by the picked side's load (starter_out / no_starter_out / unknown). D18.6 The term: `-(sum over counted starters of weights[pos_group] * status_mult[status])` per side, `elo = elo_home - elo_away` added last to `d_total`; a QB on the report is the QB term's business and never counts. Tuned by coordinate descent on 2010-2024 (`make tune`, grid {0,5,10,15,20,30}); THE GATE: `enabled` may be true only when the 2025 holdout Brier improves by >= `improvement_required` (0.0005) — `validate_model` rejects an enabled term that has not earned it. Verdict 2026-10-13: 0.21606 -> 0.21516 (-0.00090), ENABLED, weights OL 10 / WR_TE 20 / RB 30 / DL_EDGE 0 / LB 30 / DB 10, mult Out 1 / Doubtful 0.75 / Questionable 0.25 / Probable 0.1. Application mode is PREGAME (term added at forecast time on the plain replay; the hook-injected replay mode failed the gate, -0.00019, and is recorded as `injury_tuning.alternative` only). Caveats on the page: one holdout season, the report is the league's word not a medical fact, a starter is whoever the depth chart lists. D18.7 (review fixes, 2026-10-13 evening). (a) Frozen cards: `freeze_official` folds the SNAPSHOT's `injury_elo` (0 for the 14 Week-5 snapshots written before the term) into `factors.d_total`, re-derives `model_spread`, and the sentence/eyebrow describe what the frozen number carried versus the latest report (CONTRACT 2.6/2.6a/2.9) — the page recovers the carried term from factors, no 8th key in 2.6b. Self-resolving: every snapshot since D18 carries `injury_elo`. (b) The enabled sentence gives the term as "N Elo points, or S points on the spread" (same form as home field) and lists Questionable starters once they move the number; the D18.4 trigger (Out/Doubtful only) is unchanged, so a Questionable-only load shows on the card eyebrow but earns no sentence. (c) The gate is weak evidence, recorded as such: on the 285-game holdout the paired per-game Brier difference is -0.00090 with SE 0.00200 (t = -0.45; bootstrap 95% CI [-0.00487, +0.00291]; P(delta <= -0.0005) = 0.59), i.e. the required 0.0005 is a quarter of one SE, and the application mode (pregame) was chosen after seeing which mode passed. PRE-REGISTERED for the next re-gate (2026 as holdout, season end): the mode is pregame (the one the build applies) and the rule is unchanged; the replay mode is not a fallback. (d) Known scheme artifacts, documented on the page, not re-tuned: an edge rusher is DL_EDGE (weight 0) or LB (30) by the club's chart slot name, and a fullback at rank 1 counts as an RB starter; 2025 is the only timestamped depth-chart season. (e) CI: `daily.yml` restores the season files from `actions/cache` so a nflverse outage reuses the last good files; a degraded build with the term enabled logs a WARNING naming the snapshots written without the reports (it still publishes, per D18.1); `RealDataSmokeTests` is structural-only under `GITHUB_ACTIONS`. (f) `covered_by_qb_term` is `pos_group == "QB"` for every QB on the report (CONTRACT 2.6b), not only the listed starter — confirmed, not changed; `qb_listed` carries the listed starter's status.
