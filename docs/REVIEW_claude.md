## Problems in the spec (must fix in the plan)

1. **Odds API credit math is wrong.** The Odds API bills credits = markets x regions per request. markets=h2h,spreads,totals with regions=us costs 3 credits, so the 500/month free tier is ~166 requests, not 500. Fix: Worker caches 15 min (not 10) using the Cloudflare Cache API (in-memory module state does not survive across isolates, so a naive `let cache` is not a cache); page only triggers a fetch on load; build fetches once/day. Budget: ~30 build fetches + ~100 page-triggered fetches/month = ~390 credits. Add a credit counter from the `x-requests-remaining` response header into model.json/footer so Lauren can see the burn.
2. **Pick log needs odds at build time, but odds are browser-only in the spec.** picks.jsonl records best_price/best_book/ev "at pick time" yet the build (GitHub Actions) never calls the odds feed. Fix: build.py calls The Odds API directly when ODDS_API_KEY is in the environment (Actions secret), else logs CSV lines with source="csv". The Worker remains for the live page.
3. **Open Worker = anyone can burn the credits.** Fix: Worker checks the Origin/Referer against an allowlist (the Pages domain + localhost), returns 403 otherwise; caches globally so even abuse costs at most 1 request per 15 min.
4. **Blend weight fit on the holdout = leakage.** Fit w on 2015-2024 closing lines, report 2025 Brier for model / market / blend separately in params.json. Also: blend Brier will come out BELOW the market Brier only if the model adds information; report whichever it is honestly.
5. **QB update double-counts.** Q and R both move by (s - p) on every game, so a team's total update is effectively K+KQ and the QB soaks up team-level results. Acceptable because KQ is tuned and gated on holdout Brier, but the gate must compare against the no-QB Brier using the SAME holdout code path. Also: a rookie or new starter starts at -50 like a backup; for upcoming games where the listed starter has NO history (first career start) say so in the rationale rather than calling them "48 points below the usual starter".
6. **Tier names inconsistent.** Confidence table says Toss-up/Lean/Strong/Lock-ish; the front-end table says Lean/Lean+/Strong/Lock-ish. Use Toss-up/Lean/Strong/Lock-ish everywhere.
7. **Predicted-score fallback.** "Team's season average points for/against" is noisy in weeks 1-3 (and undefined in week 1). Fallback: league average total over the last full season (2025 mean total) blended with season-to-date as games accrue. Keep it simple: use market total from the CSV (nflverse total_line is present for all 2026 games), then the feed, then the league-average constant.
8. **"Today" view timing.** Build is 10:00 UTC; the browser computes "today" in local time. Define today = games whose local kickoff date equals the viewer's local date; if none today, show the next slate with a "Next: Sunday" label instead of an empty page.
9. **Sim speed.** 10k runs x ~200 remaining games in pure Python with the playoff bracket is likely 15-30 s, over the 5 s budget. NumPy is already installed (2.4.2); allow it for simulate.py only, keep elo.py stdlib.
10. **Parlay legs are not independent** within a slate in a mild way (shared-market vig is independent, but correlated outcomes exist via weather/totals; for moneylines the independence assumption is standard). Keep, but the copy should say legs are treated as independent.
11. **Closing-line value** needs a comparable price: pick-time best price (feed) vs nflverse closing moneyline (consensus). Different sources, so CLV is biased in favor of the pick. Compute CLV on the CONSENSUS price at pick time vs CSV close, and show best-price CLV as a secondary number.
12. **GitHub hosting is fine here** (this is not work-related). Recommend a personal repo (grimoireart) not the Gryfin org: the product is a hobby cross-check and should not sit next to the Gryfin product repos.
13. **Open question defaults:** books = DraftKings, FanDuel, BetMGM, Caesars, user-togglable in the page (localStorage); parlay ranking = EV with hit probability beside it, plus a "most likely" sort toggle; tiebreak = keep the Elo-jitter approximation for v1 with the note on the page.
14. **Data trust:** nflverse QB names for upcoming games are "expected starters" and can lag an injury by days. The rationale's QB sentence must say "listed starter" and the pick log must store the name the model used.
15. **Elo deltas in the Why? text use team display names** ("Kansas City rates 72 points above Denver"). Spec requires ranks ("4th vs 19th") - computed from the current ratings table.
16. **Weeks with no market line in the CSV** (nflverse lines are filled a few days before kickoff, sometimes missing): card must show "model only" and tiers from p_model.
17. Spec's "Season rollover takes 1600 to 1560" is REV=0.4: 1500+100*0.6=1560. Correct.
18. The rationale rule "no sentence contains a number not in model.json" means model.json must carry every number used (rank, elo gap, HFA pts, HFA spread pts, Q diff, rest days, form delta, market pct, blended pct, predicted score). Define a per-game `factors` object as the single source for both the text and the card.
